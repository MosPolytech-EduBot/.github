# Как работать в проекте EduBot

Все задачи, сроки и результаты — на доске GitHub Projects. Telegram — для разговоров, Диск — для файлов.
Если договорились о чём-то в чате, тот же человек сразу создаёт или обновляет задачу на доске.

## Для всех (нужен только браузер)

### Взять задачу
1. Откройте доску → вид «Бери любой» или колонку «Готово к работе» своего направления.
2. Откройте задачу → справа **Assignees → assign yourself**.
3. Перетащите карточку в «В работе».

### Создать задачу
**New issue → Задача.** Заполните направление, критерий регламента, «что сделать» и «как поймём, что готово».
Задача без ответа на «как поймём, что готово» — это не задача, а пожелание.

### Сдать результат
1. Положите файл на Диск в папку своего направления. Имя: `#14_2026-11-03_кронштейн-лидара_v2.pdf`.
2. В комментарии к задаче: ссылка на файл и/или скриншот (перетащите картинку прямо в поле комментария) и две строки:
   - **Сделано:** …
   - **Дальше / не получилось:** …
3. Перетащите карточку в «На проверке» и отметьте (@) того, кто проверит.
4. Проверяющий смотрит и переводит в «Готово». Закрывает задачу не автор.

### Застряли
- Ждёте чужую работу → метка `ждёт` и в описании номер задачи, которую ждёте (`ждёт #8`).
- Нужно решение лидера → метка `вопрос`.
- Ваша задача держит других → лидер ставит ей метку `блокер`, её делаем первой.
- Нечем заняться → вид «Бери любой».

## Для тех, кто пишет код

```bash
git switch main && git pull
git switch -c 12-imu-driver          # номер задачи + пара слов
# ... работа ...
git add -p                            # добавлять осознанно, а не всё подряд
git commit -m "feat: драйвер IMU по I2C, чтение кватерниона"
git push -u origin 12-imu-driver
gh pr create --fill                   # или кнопка Compare & pull request на сайте
```

- В `main` напрямую не пушим. Всё через pull request и одно одобрение коллеги.
- В описании PR пишем `Closes #12` — при слиянии задача закроется сама.
- Типы коммитов: `feat` (новое), `fix` (исправление), `docs` (документация), `test` (тесты), `refactor` (переделка без изменения поведения), `chore` (служебное).
- В каждом репозитории README: что это, как запустить, структура папок.
- Не коммитим: пароли, токены, ключи Wi-Fi, папки сборки (`build/`, `.pio/`, `node_modules/`), исходники CAD. Исходники CAD — на Диске, в Git — экспорт (PDF, STEP, STL).
- В конце каждого спринта лидер направления делает релиз с тегом `v0.1`, `v0.2`… Список изменений из релиза идёт на слайд «Что сделано».

## Ритм

| Когда | Что |
| --- | --- |
| Понедельник, начало пары | 15 минут: сделал / беру / мешает. В первый понедельник спринта — планирование |
| Среда | Демо: каждое направление показывает результат на экране или на столе |
| Пятница вечером | Каждый обновляет свои карточки и прикладывает результаты |
